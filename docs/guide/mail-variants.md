# Почта: шаги, варианты и исходы

Основы карты (персонаж, шаг, стрелки, песочница) описаны в «[граф шагов](page:mail-graph)». Здесь подробности по каждому полю.

## Персонаж

«+ Персонаж»: «Адрес» (`имя@машина`, строчными, уникален) и необязательное «Имя». Карточка: «Адрес», «Имя в письмах», «Подпись», «Заметка автора».
Если персонажа удалить, вместе с ним уйдут его сценарии, а письма на этот адрес станут возвращаться от `MAILER-DAEMON`.
Подпись и заметка правятся совместно, как и всё остальное в Студии.

Сценарий создаётся кнопкой «+ Сценарий»: «Название» и «Идентификатор для хука mail» (слаг пишется сам из названия, пока вы не правили его руками; латиница, цифры, `-`, `_`).
Новый сценарий уже содержит шаг `start`.

## Шапка сценария

Над картой: название, «имя · адрес» персонажа, «Удалить» и «Сохранить» (без названия сохранить нельзя).
Вкладки справа: «Сценарий» (или «Шаг …», если шаг выбран), «Песочница», «Проверка» (с числом проблем).
Вкладка «Сценарий» содержит выбор персонажа, идентификатор, «Заметку автора» (для себя: где игрок берёт пароль, что проверить) и число шагов.

Сохранить сценарий с ошибками можно: Студия предупредит «Сохранено, но в сценарии есть ошибки: см. «Проверка»».
Отказ при сохранении только на грубые вещи: шаг без имени, два шага с одним именем, неверный идентификатор, пустое название, нет персонажа, занятый слаг.

## Карта

- **«+ Шаг»** ставит новый шаг в центр видимой области (`step`, `step-2` …).
- **Стрелка** это переход: тяните точку выхода варианта на шаг. Стрелку можно бросить и на тело шага. Выбранную стрелку убирает `Delete`.
- **Расстановка ручная.** Позиции шагов сохраняются. Автоматически шаги раскладываются только один раз, когда сценарий открыт впервые и у всех шагов нулевые координаты.
  Кнопки «упорядочить» нет.
- **Метки на шаге:** «начало» (игрок пишет первым), «первый» (с него сценарий начинается по хуку), значки ошибок и предупреждений, строка «✉ тема · N с».
  У вариантов значок `↪` значит пересылку, «усл.» значит условный вариант.
- **Удаление шага** спрашивает подтверждение и сообщает, сколько переходов на него уберётся.
- **Переименование шага** автоматически переписывает все переходы на старое имя.
- Каждый шаг это отдельное поле общего черновика: два автора могут одновременно править разные шаги.

## Шаг

- «Имя шага» (пробелы превращаются в `-`).
- Галочка **«Начало переписки»**: варианты шага видны игроку, который сам пишет персонажу.
- **Письмо персонажа:** «Письмо» (без письма, новое письмо или существующее из объектов формата `msg`), задержка в секундах, «Тема», «Текст письма».
  Пустые тема и текст значат «шаг без письма». Если выбрано существующее письмо, правка меняет его везде, где оно используется.
  В тексте работают подстановки `{player}`, `{login}`, `{to}`, `{date}`, `{address}`.
- **Варианты ответа игрока:** «+ вариант», стрелки порядка и «✕».

Письмо шага хранится как объект формата `msg` (слаг от `<сценарий>-<шаг>`) с заголовками `From` (адрес персонажа), `To: {to}` и `Subject`.
Заголовки `X-Label` и `X-Label-Tone` (метка и её тон в списке игрока) в редакторе сценариев **не редактируются**: если они нужны, их пишут в самом файле письма,
и при сохранении сценария чужие заголовки остаются нетронутыми.

## Вариант

![Редактор варианта](shot:studio-mail-variant)

| Поле | Что значит |
|---|---|
| «Подпись в списке ответов» | текст кнопки у игрока (обязательно) |
| Режим «Ответ или новое письмо» / «Пересылка письма» | для пересылки нужно выбрать, какое письмо игрок пересылает |
| «Текст, который игрок набирает» | текст с секретом и выбором слов (см. ниже); пусто: вариант отправляется сразу, без набора |
| «Условие по ключам» | вариант открывается, когда выражение из ключей верно |
| «Нужны метки», «Мешают метки» | вариант доступен, если у игрока есть все первые и нет ни одной из вторых |
| «Только если пишет с учётки» | вариант только для одной учётки |
| «Если недоступен» | «Закрытый виден как «???»» или «Скрыт» |
| «Что приложить» | ничего, «этот объект», «этот ключ», «документ, подписанный ключом» (плюс слаг) |
| «Попыток» | ноль значит без ограничения |

Под полем текста Студия показывает «Как увидит игрок»: секрет точками по длине, выбор как `a / b`.
Сверка текста не различает регистр, лишние пробелы и «е»/«ё».

### Секрет и выбор

- `{{секрет}}`: игрок видит только длину и должен знать значение сам. Что он наберёт в этом месте, проверит сервер: неверное значение даёт исход «неверно» и тратит попытку.
- `[[склад 7|склад 9]]`: игрок выбирает слово, и у каждого слова свой выход.

## Исходы

Выходы справа у варианта:

| Выход | Когда |
|---|---|
| «верно» | текст верен (если у выбранного слова нет своих действий, срабатывает он) |
| «слово» | по одному на каждое слово выбора |
| «неверно» | есть секрет, вложение или лимит попыток, и ответ не подошёл |
| «попытки кончились» | лимит больше нуля и попытки потрачены; без своих действий берёт действия «неверно» |

У каждого выхода список действий («+ действие»):

| Действие | Что делает |
|---|---|
| «Перейти на шаг» | переход, можно с задержкой в секундах. Стрелка на карте и есть это действие |
| «Прислать письмо» | письмо от персонажа (существующее или новое), с задержкой |
| «Поставить метку», «Снять метку» | метка игрока, по ней работают «Нужны метки» и «Мешают метки» |
| «Выдать ключ» | кладёт ключ в секреты игрока |
| «Положить файл» | объект по слагу и путь на машине, например `/home/{login}/file.txt` |
| «Засыпать окнами ошибок», «Открыть окно», «Выбросить из сессии» | эффекты в браузере игрока |
| действия мира | метка и счётчик мира, новость, эфир, письмо всем, запись на форуме |
| «Вернуть как недоставленное» | письмо игрока возвращается от `MAILER-DAEMON` |

Полный список и где что доступно — в разделе «Действия». Задержка есть только у перехода и письма. Метки и ключи это то, чем выход одной загадки открывает следующую.
