# Почта: варианты ответа

Игрок пишет персонажам не что угодно: он выбирает вариант ответа и перепечатывает его текст. Варианты — **возможности** сценария
с каналом «письмо»: вариант описывает нода-сущность «Возможность», открывает «Возможность: Изменить» (глава «[Сценарии](page:world-graph)»).
Разговор складывается из обычных нод: письмо персонажа («Персонаж: Отправить письмо»), за ним «Открыть» вариантов ответа,
а «Возможность: Использована» ведёт дальше.

## Персонаж

Раздел «Почта» в Студии: адреса персонажей. «+ Персонаж»: «Адрес» (`имя@машина`, строчными, уникален) и необязательное «Имя».
Карточка: «Адрес», «Имя в письмах», «Подпись», «Заметка автора». Адрес можно связать с персонажем мира (раздел «Персонажи») —
тогда варианты можно адресовать персонажу, а не адресу. Письмо на адрес, которого нет, возвращается от `MAILER-DAEMON`.

## Возможность (канал «письмо»)

| Поле | Что значит |
|---|---|
| Как | переключатель Новое · Ответ · Пересылка и вход для письма. Пусто — ответ на любое письмо адресата (пересылка любого письма). Письмо на входе (объект — любая его копия, размещение — этот файл; провод «Письмо» с «Персонаж: Отправить письмо») — ответ на него или его пересылка, «Новое» тогда пропадает |
| Кому | адрес текстом или персонаж проводом с «Персонаж» (любой его адрес); можно списком |
| Подпись | текст кнопки в списке у игрока |
| Текст для набора | что игрок перепечатывает (см. ниже); пусто — вариант уходит сразу, без набора |
| Вложение | объекты или размещения (одно или список): игрок должен приложить один из них. Пусто — ничего не нужно. Подпись документа и прочее проверяет сценарий после отправки — по выходу «Вложение» у «Использована» |
| С учётки | вариант только для этой учётки (`логин@хост`) |
| Группа | верный ответ закрывает все возможности группы |

«Возможность: Изменить» — провод «Возможность» с этой ноды, «Для кого» (Игроку хода · Всем) и состояние: **Открыть**,
**Показать «???»** (игрок видит вариант закрытым и выбрать его не может) или **Скрыть** (по умолчанию вариант скрыт).
Во «Когда» идёт поток (открыть сейчас) или условие «да/нет» (открыта, пока условие верно у игрока, — так делают вариант, который
игрок видит с самого начала: «Да/нет» → «Когда»).

### Секрет и выбор

- `{{секрет}}`: игрок видит только длину и должен знать значение сам. Неверное значение — неверный ответ.
- `[[склад: 7|9]]`: развилка, игрок выбирает слово. У «Возможность: Использована» она становится выходом «склад» с выбранным словом;
  без имени — «Развилка 1», «Развилка 2»… Имя — до двоеточия с пробелом: `[[12:00|13:00]]` — развилка без имени.

Сверка не различает регистр, лишние пробелы и «е»/«ё». Если набран не тот текст, письмо не уходит и ответ не засчитывается.

## Чем кончилось

«Возможность: Использована» с проводом «Возможность» с варианта: **Верно** (текст и секрет совпали, вложение то; возможность и её
группа закрываются), **Неверно**. Выходы данных: развилки текста, возможность, набранный текст, письмо игрока в «отправленных»
(размещение), вложение (размещение приложенного файла), учётка, игрок. Лимит попыток — счётчик игрока по «Неверно» (глава «[Сценарии](page:world-graph)», «Возможности»).

Письмо персонажу без варианта ждёт автора во входящих персонажа (лента кукловода) и ловится «Персонаж: Получил письмо».

## Пример: охрана порта

В демо-мире сценарий «Dock access»:

1. «Да/нет» → «Когда» у «Возможность: Открыть» варианта «Ask for dock access» (новое письмо `guard@aether-core`) — он виден всем.
2. «Использована → Верно» → письмо `guard-ask` → «Открыть» ответ «Give the password» (`Password: {{hunter2}}. Dock [[dock: 7|9]], please.`, группа `ask`).
   Рядом «Mention the tunnel» той же группы: «Показать «???»» с «Да» во «Когда» и «Открыть» с «Фактом» `tag:tunnel` — без тега вариант виден как «???».
3. «Использована» пароля: «Верно» → «Условие» по «Сравнить» (развилка `dock` = `7`): да — письмо `guard-open` и тег `dock-open`,
   нет — письмо про ремонт и снова «Открыть» пароль. «Неверно» → счётчик `dock_tries` +1 → «Условие» `count:dock_tries>=3`:
   да — «Скрыть» пароль и `guard-closed`, нет — `guard-wrong`.
