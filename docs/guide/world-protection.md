# Защита файлов: слои и реакции

У объекта на вкладке «Защита» и у размещения («Защита места…») две независимые вещи: **условие доступа** (по ключам, см. [ключи](page:world-keys)) и **слои защиты**.
Сначала проверяется условие, потом игрок снимает слои командами.

![Защита объекта](shot:studio-item)

## Слои

Слои идут сверху вниз: верхний игрок снимает первым. Под каждым слоем Студия показывает, как игрок его снимет.

| Слой | Параметры | Команда игрока |
|---|---|---|
| `corrupted` «Повреждён» | нет | снять нельзя, только описание |
| `damaged` «Повреждён после ошибки игрока» | нет | `rpr файл` (обычно слой добавляет реакция `add damaged`) |
| `encrypted` «Зашифрован» | `password`, `key`, `attempts` (по умолчанию 3) | `ward файл пароль` или `ward -k ключ файл` |
| `shifted` «Данные со сдвигом» | `skip` (блоков по 512 байт), `count`, `out` | `blk файл skip=N` |
| `binary` «Необычная кодировка» | `encoding` | `cvt enc кодировка файл` |
| `disguised` «Замаскирован под другой формат» | `format` | `cvt ext файл файл.формат` |

Для каждого слоя можно задать:

- **«После снятия слоя файл»**: остаётся как есть, переименуется (`->`) или копируется (`=>`) по новому пути.
- **«Ответы на команды»**: собственный ответ слоя на `ftyp`, `cnt`, `ward`, `pak`, `rpr`, `blk`, `cvt` (в тексте доступны `{path}` и `{name}`).
- **«События»**: реакции, см. ниже.

Если на файле не тот слой, который пытается снять команда, попытка не засчитывается.

## События и действия

События слоя:

| Событие | Когда |
|---|---|
| `remove` «Слой снят» | один раз |
| `attempt` «Неудачная попытка» | на каждую неверную попытку |
| `fail` «Попытки кончились» | один раз; блокировки при этом нет, слой всё равно можно снять правильным паролем |
| `read` «Файл открыт» | на каждый `cnt`, слой остаётся |
| `delete` «Файл удалён» | при `del` |
| `restore` «Файл возвращён из корзины» | при `rcvr` |

Что можно сделать в ответ на событие:

| Действие | Что делает | Пример |
|---|---|---|
| `say` | сказать игроку | `Осталось попыток: {attempts_left}` |
| `log` | записать в журнал | `Файл вскрыт: {path}` |
| `add` | добавить слой | `damaged` |
| `drop` | удалить файл | `/home/secret.dat` |
| `rename` | переименовать | `opened.txt` |
| `copy` | скопировать | `backup/copy.txt` |
| `mail` | прислать письмо или запустить разговор | `door_open delay=30` (задержка до 7 суток) |
| `kick` | выбросить игрока из сессии | без аргументов |
| `alert` | засыпать окнами ошибок | `unreachable count=12 gap=300` (до 40 окон, пауза 100–5000 мс) |
| `open` | открыть окно | `apps/wiki/go/harbor/` (внутренний адрес без `/` в начале) |

Реакция, написанная в файле, заменяет реакцию слоя по умолчанию для этого события.
Счётчика попыток у игрока нет, поэтому `say` с `{attempts_left}` единственный способ его показать.

## Текстовая запись

Конструктор и текст всегда равны друг другу: текст источник правды, конструктор переписывает заголовки слоёв.
Если текст не разбирается, конструктор отключается и показывает ошибки с номерами строк.

```
# комментарий
> имя главный_аргумент имя=значение    слой
-> путь                                 после снятия переименовать
=> путь                                 после снятия скопировать
команда: ответ                          ответ слоя на команду
on событие: действие                    реакция в одну строку
on событие:
- действие                              реакция списком
```

### Примеры

Пароль, три попытки:

```
> encrypted hunter2 attempts=3
```

Ключ вместо пароля, с подсказкой и наказанием:

```
> encrypted key=cardkey attempts=2
on attempt: say "Осталось попыток: {attempts_left}"
on fail: add damaged
```

Файл притворяется PDF, после снятия переименовывается и присылает письмо:

```
> disguised pdf -> report.pdf
on remove:
- say "Это был PDF"
- mail door_open delay=30
```

Два слоя: сначала кодировка, потом сдвиг:

```
> binary rot13
file: Неизвестный формат
> shifted skip=4 count=2 out=data.bin
on read: log "Файл прочитан: {path}"
```

## Защита места

По умолчанию размещение защищено так же, как объект. «Защита места…» позволяет задать для одного места своё условие или свои слои, либо снять защиту объекта.
Для условия и для слоёв есть варианты «как у объекта», «своё», «нет». Так один и тот же объект на разных дисках или машинах закрывается по-разному.

## Как проверить

Блок «Что получит игрок» показывает первые байты так, как их покажут `blk` и `txtx`: без слоёв и со слоями из редактора.
Объект можно открыть «С ключами» и «Без ключей». Всё остальное проверяется входом игрока и прохождением пути.
